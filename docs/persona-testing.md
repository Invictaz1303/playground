# Persona Testing — ทดสอบแอปด้วยผู้ใช้จำลอง 6 แบบ

ใช้กรองปัญหารอบแรกก่อนส่งให้คนจริงลอง (ไม่ได้แทนการทดสอบกับคนจริง)
ใช้กับแอปของเราเองบนเครื่องหรือ staging เท่านั้น ห้ามทดสอบบนระบบจริง

## 6 บทบาท และวิธีจำลองทางเทคนิค

ส่วนที่ได้ผลจริงคือการตั้งค่าเบราว์เซอร์ให้ตรงกับแต่ละบทบาท ไม่ใช่แค่สั่งให้ AI สมมติตัว

| บทบาท | ตั้งค่า / สิ่งที่ทำ | สิ่งที่ต้องดู |
|---|---|---|
| 👵 อายุ 65 ไม่ถนัดเทคโนโลยี | ซูม 200%, ตัวอักษรใหญ่ | ปุ่มเล็กเกินไหม (ควร ≥ 44px), ข้อความ error เข้าใจง่ายไหม, ศัพท์เทคนิค |
| ⚡ คนใจร้อน | กดปุ่มรัว ๆ, กดก่อนโหลดเสร็จ, จำลองเน็ตช้า (Slow 3G) | ส่งข้อมูลซ้ำไหม, มี loading state ไหม, ปุ่มถูก disable ระหว่างบันทึกไหม |
| 📱 จอมือถือเล็ก | viewport 375×667 (iPhone SE) | ปุ่มล้น, ตัวหนังสือซ้อน, ต้องเลื่อนแนวนอน, ตาราง/กราฟอ่านไม่ได้ |
| ⌨️ คีย์บอร์ดล้วน | ใช้แค่ Tab / Shift+Tab / Enter / Esc | ไปถึงทุกปุ่มไหม, เห็น focus ไหม, ติดอยู่ใน modal ไหม |
| 🆕 เข้าเว็บครั้งแรก | ล้างคุกกี้และ localStorage ก่อนเริ่ม | รู้ไหมว่าต้องเริ่มตรงไหน, หน้าว่าง (empty state) บอกอะไรไหม |
| 💥 ตั้งใจทำให้พัง | กรอกช่องว่าง, อีโมจิ, ข้อความยาวมาก, ตัวเลขติดลบ/ทศนิยม/ตัวอักษรในช่องตัวเลข, กด Back กลางทาง | validation, ข้อความ error, ข้อมูลเสียหายไหม, หน้าขาวไหม |

## สำหรับ KPI tracker โดยเฉพาะ — งานหลักที่ควรให้ทุกบทบาทลอง

1. สร้าง KPI ใหม่ (ชื่อ, เป้าหมาย, หน่วย, รอบเวลา)
2. บันทึกค่าจริงของ KPI
3. ดูความคืบหน้า / กราฟ / dashboard
4. แก้ไขและลบ KPI

จุดที่มักพังในแอปแนวนี้: ค่าเป้าหมายเป็น 0 (หารด้วยศูนย์ → % ผิด), ตัวเลขติดลบ, ทศนิยมยาว, วันที่ข้ามเดือน/ปี, KPI ที่ยังไม่มีข้อมูล

## วิธีรัน

**แบบ A — Claude Code + Playwright script (แนะนำ ประหยัดโควตา รันซ้ำได้)**
บอก Claude ว่า "รัน persona testing ตาม docs/persona-testing.md กับแอปที่ [URL]"

**แบบ B — Playwright MCP (สำรวจคล่องกว่า แต่กินโควตามาก)**
```
claude mcp add playwright npx @playwright/mcp@latest
```
แล้วใช้พรอมต์:

> ใช้ Playwright เปิดแอปที่ [URL] สร้าง subagent 6 ตัวตามบทบาทใน docs/persona-testing.md
> ให้แต่ละตัวลอง [งานหลัก] ด้วยบัญชีทดสอบโดยไม่มีคนช่วย ใช้การตั้งค่าเบราว์เซอร์ตามตาราง
> ถ่ายภาพหน้าจอระหว่างทาง รายงานจุดที่ลังเล สับสน หรือทำไม่ได้
> แล้วจัดอันดับ 10 จุดที่ควรแก้ตามจำนวนบทบาทที่เจอ

ข้อควรระวัง: ให้ subagent รันทีละตัว หรือแยก browser context กัน ไม่งั้นจะแย่งเบราว์เซอร์ตัวเดียวกัน

## ผลลัพธ์ที่ต้องการ

- ตารางว่าบทบาทไหนติดตรงไหน (พร้อมภาพหน้าจอ)
- 10 จุดที่ควรแก้ เรียงตามจำนวนบทบาทที่เจอ แล้วตามความรุนแรง
- หลังจากนั้นให้คนจริงในกลุ่มเป้าหมายลองอย่างน้อย 2–3 คน
